## 1. Principles

- **Code/data separation**: almost all vulnerabilities (SQL injection, XSS, file inclusion, command injection) arise when data is interpreted as code. The defense is structural (bound parameters, automatic escaping, argument arrays), not filtering "dangerous" characters.
- **Trust boundary**: everything that comes from outside is external input — `$_GET`, `$_POST`, `$_COOKIE`, `$_FILES`, many `$_SERVER` keys (`HTTP_*`, `REQUEST_URI`, `PHP_SELF`), the request body, headers, data read from third-party APIs, uploaded files, even database rows written by other systems.
- **Validate on input, escape on output**: validation guarantees that the data makes sense for the domain; escaping depends on where the data ends up. They are two different operations and both are needed.
- **Explicit authorization** on every action and every resource (checking that the user may act on *that* row, not just that they are authenticated).

## 2. Input: validation at the boundary

```php
$id = filter_var($raw, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1], 'flags' => FILTER_NULL_ON_FAILURE]);
$email = filter_var($raw, FILTER_VALIDATE_EMAIL, FILTER_NULL_ON_FAILURE);
$flag = filter_var($raw, FILTER_VALIDATE_BOOL, FILTER_NULL_ON_FAILURE);
$status = Status::tryFrom($raw);          // backed enum for closed sets
```

- With `FILTER_NULL_ON_FAILURE`, `null` means "invalid" and `false` remains a legitimate value.
- Validate, don't "sanitize": `FILTER_SANITIZE_*` alters the data and gives a false sense of security (`FILTER_SANITIZE_STRING` has been deprecated since 8.1). Reject what is not valid.
- Immediately turn valid input into types or value objects; internal code must not revalidate.
- Check the type and structure of decoded JSON data (`is_array`, `is_string`, expected keys): `json_decode` returns anything.
- Limit sizes (string length, number of elements, body size) to prevent resource exhaustion.

## 3. Output: context-aware escaping

| Context | Technique |
|---|---|
| HTML body and quoted attributes | `htmlspecialchars($s, ENT_QUOTES \| ENT_SUBSTITUTE \| ENT_HTML5, 'UTF-8')` or a template engine with automatic escaping (Twig, Blade `{{ }}`, Plates `$this->e()`) |
| Inside `<script>` or `on*` attributes | do not insert data; pass it via `data-*` or JSON: `json_encode($data, JSON_HEX_TAG \| JSON_HEX_AMP \| JSON_HEX_APOS \| JSON_HEX_QUOT \| JSON_THROW_ON_ERROR)` |
| URL parameter | `rawurlencode()` for segments, `http_build_query()` for the query string |
| `href`/`src` with a user-supplied URL | validate the scheme (`https`, `http`, `mailto`) before escaping: `javascript:` passes through `htmlspecialchars` untouched |
| User-supplied rich HTML | dedicated sanitizer (HTML Purifier, `symfony/html-sanitizer`), never regex |
| HTTP headers | reject `\r` and `\n` in values (PSR-7 implementations already do this) |

Blade `{!! !!}`, Twig `|raw` and similar disable escaping: acceptable only on content that is already sanitized or generated by the application.

## 4. SQL

- Always prepared statements with bound parameters (details in `database-pdo.md`). Manual escaping (`addslashes`, `real_escape_string`) is not an acceptable defense.
- **Identifiers** cannot be bound as parameters: columns, tables and sort directions come from a whitelist.

```php
$column = match ($request['sort'] ?? 'created_at') {
    'name' => 'name',
    'created_at' => 'created_at',
    default => throw new InvalidArgumentException('Sort order not allowed'),
};
$direction = ($request['dir'] ?? 'asc') === 'desc' ? 'DESC' : 'ASC';
```

- In `LIKE`, escape `%`, `_` and the escape character in the bound value, if the user must not be able to use wildcards.
- Principle of least privilege for the application's database user.

## 5. Passwords, tokens, cryptography

**Passwords**
```php
$hash = password_hash($password, PASSWORD_DEFAULT);           // bcrypt, cost 12 since 8.4
if (password_verify($password, $hash)) {
    if (password_needs_rehash($hash, PASSWORD_DEFAULT)) {
        // update the stored hash: the default algorithm or cost has changed
    }
}
```
- `PASSWORD_ARGON2ID` if available and if you want resistance to GPU attacks; configure memory/time cost with a benchmark on the server.
- bcrypt only considers the first 72 bytes: if passwords can be longer, prefer Argon2id or enforce a limit; do not pre-hash with `hash()` without knowing what you are doing.
- The salt is included in the hash: no separate column. Never fast hashes (`md5`, `sha*`) or reversible encryption for passwords.
- `#[\SensitiveParameter]` on parameters that receive passwords or secrets.

**Tokens and random values**
- `bin2hex(random_bytes(32))` for tokens, `random_int($min, $max)` for numbers. `rand`, `mt_rand`, `uniqid`, `lcg_value` and `str_shuffle` are not cryptographically secure.
- Compare secrets with `hash_equals($known, $userSupplied)` to prevent timing attacks.
- Store the hash of long-lived tokens (password reset, API keys) in the database, not the plaintext token.

**Cryptography**
- Use `ext-sodium` (`sodium_crypto_secretbox`, `sodium_crypto_aead_xchacha20poly1305_ietf_*`, `sodium_crypto_box` for public key) or the framework's abstraction (Laravel `Crypt`). Never ECB mode, never encryption without authentication, never home-made algorithms.
- Keys outside the code, generated with `sodium_crypto_secretbox_keygen()` or equivalent, rotatable.
- Hashing is not encryption; base64 is neither.

## 6. Files, uploads, paths, commands

**Uploads**
- Do not trust the file name and MIME type sent by the client. Determine the type from the content (`finfo_file(..., FILEINFO_MIME_TYPE)`) and compare it against a whitelist; check the extension too.
- Store outside the document root with a generated name (`bin2hex(random_bytes(16))`), serve the file through code that sets `Content-Type` and `Content-Disposition`.
- Check `UPLOAD_ERR_OK`, the maximum size, and use `move_uploaded_file()` (or the PSR-7 API `UploadedFileInterface::moveTo()`).

**Paths**
- Never build paths from raw input. If needed, resolve with `realpath()` and verify that the result starts with the allowed base directory (plus the separator).
- Never `include`/`require` with user input; `allow_url_include=Off`.

**System commands**
- Avoid them if a PHP alternative exists. If they are needed, use `proc_open` with an **array** of arguments (no shell involved) or `symfony/process`; as a last resort `escapeshellarg()` on every argument. Never `shell_exec`/backticks with external data.

## 7. Sessions, cookies, CSRF, headers

- `session_regenerate_id(true)` on every privilege change (login, logout, elevation).
- Settings: `session.use_strict_mode=1`, `session.cookie_httponly=1`, `session.cookie_secure=1`, `session.cookie_samesite=Lax` (or `Strict`), `session.use_only_cookies=1`.
- Application cookies with `setcookie($n, $v, ['secure' => true, 'httponly' => true, 'samesite' => 'Lax', 'path' => '/'])`.
- CSRF: per-session synchronizer token verified with `hash_equals` on every state-changing request; `SameSite` reduces the risk but does not replace the token. `GET` requests must not change state.
- Useful headers: `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `frame-ancestors` in the CSP (or `X-Frame-Options`). Set them in a middleware.

## 8. Deserialization, XML, outgoing requests

- `unserialize()` on external data allows object injection (gadget chains). Use JSON. If `unserialize` is unavoidable on semi-trusted data: `unserialize($s, ['allowed_classes' => false])` or an explicit list.
- XML: since PHP 8.0 with libxml ≥ 2.9, external entities are disabled by default. Do not pass `LIBXML_NOENT` or `LIBXML_DTDLOAD` on untrusted XML.
- SSRF: if the application fetches user-supplied URLs, validate scheme and host against a whitelist, resolve the host and reject private/loopback/link-local addresses, disable redirects or revalidate them, set timeouts.
- Regular expressions on external input: limit the input length and avoid patterns with catastrophic backtracking; check the return value of `preg_*` (`false` = error, `preg_last_error_msg()`).

## 9. Production configuration and dependencies

```ini
display_errors = Off
display_startup_errors = Off
log_errors = On
error_reporting = E_ALL
expose_php = Off
allow_url_include = Off
session.use_strict_mode = 1
session.cookie_httponly = 1
session.cookie_secure = 1
```

- The document root points only to `public/`: configuration, `.env`, `vendor/`, logs and sources stay outside.
- Secrets in environment variables or in a secret manager, never in the repository; `.env` in `.gitignore`, `.env.example` without real values.
- Generic error messages to the user, details only in the log. Never print `$e->getMessage()` of infrastructure exceptions (they may contain DSNs, queries, paths).
- `composer audit` in CI and before every release; keep PHP updated within the supported versions.

## 10. In frameworks

Use the framework's mechanisms instead of reimplementing them. The rules in this file remain valid for the code you write outside those mechanisms, and for verifying that they are used correctly.
- **Laravel**: Form Requests/validator, policies and gates, CSRF middleware, `Hash`, `Crypt`, Eloquent/query builder with bindings (watch out for `whereRaw`, `orderByRaw`, `DB::raw`: always bind values, whitelist identifiers), `$fillable` against mass assignment, Blade `{{ }}` for escaping.
- **Symfony**: Form and Validator, Security with voters for authorization, form CSRF protection, PasswordHasher, Doctrine with parameters (never concatenated DQL), Twig with automatic escaping.
- **Laminas / Mezzio**: `laminas-inputfilter` and `laminas-validator` at the boundary, `laminas-escaper` for context-aware escaping, `mezzio-csrf` and `mezzio-authorization`.
- **Without a framework**: the native functions described above, or standalone components (e.g. `symfony/validator`, `symfony/html-sanitizer`) behind the boundary.
